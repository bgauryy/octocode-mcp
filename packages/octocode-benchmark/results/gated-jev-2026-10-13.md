# Current local MCP: JEV enabled versus disabled

**No general token saving was demonstrated.** Across 40 local and 30 GitHub questions, Terra made **zero goals requests and zero public `clasify` calls**, despite the enabled schemas being verified. Local input-token use was effectively tied. GitHub input tokens increased **12.6%** with the feature enabled. These differences concern the optional tool surface and ordinary research choices; they do not measure a JEV ranking decision.

All **140 final solver cells and 70 blind comparisons** completed. Two pre-research Terra capacity failures succeeded on their one permitted retry; their original attempts remain counted separately.

## What ran

Both arms used one frozen snapshot of the current **local `octocode-mcp` 20.2.0 build**, contract fingerprint `c9660ab16a7f7c60d9c3e23dd8ba5706ba2c73d2fcd47bd58cf8c2ffb75f77c7`. This was a fresh paired run, not a comparison against an earlier campaign.

| Setting | OFF | ON |
|---|---|---|
| Solver | `gpt-5.6-terra`, medium | Same |
| Beta | Enabled | Enabled |
| Classification API credential | Explicitly empty | Canonical configured credential |
| Ranking | Disabled | Enabled |
| Optional semantics | Absent | Goals and beta `clasify` available |
| Local MCP catalog | 5 tools; no goals | 6 tools; goals on `localSearch`, `localFetch` |
| Full MCP catalog | 12 tools; no goals | 13 tools; goals only on `localSearch`, `localFetch`, `ghSearchCode`, `ghGetFileContent` |

The benchmark harness now sets beta explicitly in both arms and checks goals against those four eligible tools. Its 45 focused tests pass. Live preflight checked catalog gates, direct and nested private-path denial, and zero question-term matches in agent-visible instructions. All 97 source matches were reviewed as generic APIs, language constructs or examples.

There was one fresh isolated solver per question and arm, with a 600-second/30-tool-call budget. Local40 ran before GitHub30; ON/OFF jobs were interleaved per question with at most four workers. The frozen retry budget allowed one infrastructure retry per cell and 14 globally; only two were used. No successful answer was rerun. All nine local clone revisions matched their manifests and had clean tracked trees.

The blind source-checking judge was **`claude-sonnet-5-5`**, using seeded X/Y labels and private local answer cards. A fresh synthetic citation check scored a supported answer 10 and a wrong-function citation 4 before scored solvers started. All 70 judgments succeeded without judge retries. All **142 attempt logs**, including the two invalid initial attempts, passed strict hash checks of every referenced artifact.

## Paired results

Ratios are **ON ÷ OFF**: below 1 means less resource use. Each question has equal weight; intervals are 95% bootstrap intervals over questions, with 10,000 resamples. Terraform is the declared Q33–Q40 subset of local40, not another independent corpus.

|---|---:|---:|---:|---:|---:|
| Local40 | 40/40 | 0.991 [0.897, 1.084] | 1.004 [0.915, 1.102] | 1.009 [0.885, 1.137] | 18/40 |
| GitHub30 | 30/30 | **1.126 [1.028, 1.231]** | **1.098 [1.006, 1.202]** | 1.041 [0.923, 1.179] | 15/30 |

The apparent Terraform input reduction is inconclusive: its interval includes an increase. No set demonstrated a clear end-to-end speed improvement: wall-time ratios were local **0.979 [0.757, 1.277]**, GitHub **0.982 [0.789, 1.223]**, and Terraform **0.866 [0.447, 1.665]**.

Median characters per question were local **10,188 OFF / 12,176 ON** and GitHub **14,523 OFF / 15,315 ON**. Pooled local input totals look lower with ON, but a few large ordinary-route differences drive that total; the question-level estimate is approximately parity.

Correctness was scored in whole points from 0–10; differences of one point or less count as ties:

| Set | ON more correct | OFF more correct | Within-one-point ties |
|---|---:|---:|---:|
| Local40 | 1 | 1 | 38 |
| GitHub30 | 2 | 0 | 28 |
| Terraform subset | 0 | 1 | 7 |

These are the unmodified blind scores. Independent source audits checked **all four** greater-than-one-point differences:

- **Local Q21, OFF 8 / ON 10:** ON cited an additional iframe test. OFF's same cross-window explanation was supported by implementation and permitted by the rubric. The judge overstated its lack of support; this is a questionable correctness gap.
- **Local Q40, OFF 10 / ON 8:** both accurately covered the asked error paths. OFF additionally included the successful `ret.Required` assignment, an explicit private-rubric item. The gap is defensible as rubric completeness; shorter output and clearer labels alone do not justify it.
- **GitHub Q13, OFF 4 / ON 10:** OFF incorrectly claimed that only `src/bitops.c` changed, missing `tests/unit/bitfield.tcl` and reporting +9/−3 rather than +18/−3. ON read both patches. The material difference is supported.
- **GitHub Q28, OFF 7 / ON 9:** ON supplied supported storage, resume and compression details that OFF omitted. Its threshold wording was too absolute: reaching the threshold establishes eligibility, subject to blockers and configuration. The direction of the quality difference is supported.

Neither GitHub quality win involved a semantic call. They show better ordinary evidence gathering in those sessions, not demonstrated JEV effectiveness.

## JEV usage

Every traced response resolved `jev-latest` to **`jev-1.13.0`**. All requests below were the fixed connectivity probe; **zero requests classified research evidence**.

| Scope | Requests | JEV input | JEV output |
|---|---:|---:|---:|
| Local valid ON sessions | 80 | 22,240 | 1,600 |
| GitHub valid ON sessions | 60 | 16,680 | 1,200 |
| Archived invalid ON attempt | 2 | 556 | 40 |
| Separate setup preflights | 4 | 1,112 | 80 |
| **All traced attempts** | **146** | **40,588** | **2,920** |

All 146 attempts succeeded with complete usage receipts. Each enabled cell starts a preflight MCP and a solver MCP, producing two startup probes. A persistent production MCP normally incurs its startup probe once per server lifetime; this benchmark's per-cell setup overhead must not be presented as a per-tool-query cost. Median probe latency was about **0.27 seconds**; that measures connectivity checks, not classification of large evidence.

Sonnet evaluation overhead is separate: 70 judge transcripts reported 470 ordinary input, 912,889 cache-read input, 633,010 cache-write input and 90,570 output tokens. The one fresh calibration reported 4 input, 3,839 cache-write and 495 output tokens. These are not Terra research or JEV usage. No dollar saving is inferred from adding tokens with different prices; Terra/JEV monetary costs were not reported.

## Interpretation and limits

Keep the feature optional; this run provides no basis for promising automatic token savings from enabling it. The configuration and schema gates work, and these agents avoided unnecessary semantic requests. **Zero use does not prove optimal selection**: it also leaves the ability to recognize a useful semantic opportunity untested. This study cannot decide whether goals or public `clasify` is the better active route.

The ON catalog added 2,724 characters locally (10,298 versus 7,574) and 3,114 in the full catalog (21,988 versus 18,874). That is real context overhead; its isolated contribution to model-token differences was not measured. Instructions, catalog presence and ordinary nondeterministic research choices can change a session even when JEV performs no research judgment.

These are previously exposed development question sets, one pass per arm, one solver model and one blind judge. Small quality gaps are judge-sensitive; all substantial gaps received source audits above. GitHub rate limits and model caching affect timing and billing. A future claim about active reranking needs a separately declared, held-out set with ambiguous evidence-discovery tasks and exact-read negative controls, with autonomous use and source-backed quality both measured.
