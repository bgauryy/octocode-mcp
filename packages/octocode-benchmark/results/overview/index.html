The questions

One selected set of code research questions on GitHub or pinned local repositories, from a single-file lookup to multi-hop traces. Each names its repositories and refs and nothing else: no hints, no answer key. Every tool answers the same set.

What is counted

Observable characters. Tool output read back into context, plus the tool calls and the final answer the agent wrote, taken from the agent's own transcript. Failed and refused calls count. System prompts, tool schemas and hidden host framing do not. Reported model tokens are measured separately; unavailable usage or timing is unknown.

The agents

A fresh headless agent answers each question with one tool setup and nothing else: no project files, settings or memory. Octocode arms get only the MCP server; gh arms get only a read-only gh through Bash.

The judge

A blind judge from a different model family sees two answers as X and Y in random order with tool names removed, verifies the ground truth against source, then scores correctness out of ten. Correctness comes first; fewer characters only break a tie.

Averaging ratios

For each question, the other tool's characters are divided by the anchor's. The headline is the geometric mean of those ratios across questions, with a bootstrap interval, so a few huge questions can't dominate.

Reproduce it

Everything lives in packages/octocode-benchmark: scripts/run_campaign.sh runs arms, judge_pair.sh judges them, matrix_summary.py builds the matrix. See the package on GitHub.
